Phase 1. Define the Project Scope Questions
Current project definition
The proposed product is an AI-powered project and task management assistant. It analyzes information distributed across emails, documents, files, calendar events, chat messages, images, and audio; identifies which items are semantically related to the same project or topic; and constructs a chronological dashboard containing discussions, meetings, files, decisions, deadlines, and action items.
Problem being addressed
People often need to reconstruct when a subject was discussed, where a file was shared, when a meeting occurred, how a decision developed, and what actions remain. Today they may have to search by keyword or sender, review multiple threads, inspect folders, and check several applications manually to construct a concrete project management assistant tool. Related information can be missed when it uses different terminology or appears in separate threads and tools.

Current target audience
Individuals and teams managing ongoing projects, tasks, or commitments across multiple communication and file-storage tools.
Potential users include project and product managers, individual professionals, freelancers, consultants, students, researchers, small-business owners, and community organizers.
The initial audience has not yet been narrowed to one primary user segment.
Current proposed solution
Understand the semantic meaning of messages and files instead of relying only on exact keyword matches.
Group related information into projects, topics, or workstreams.
Extract participants, dates, meetings, files, decisions, deadlines, and action items.
Create a chronological, source-linked project timeline on a dashboard.
Allow users to verify the AI's conclusions by opening the original source.

Current MVP approaches under consideration
Approach A - File-based prototype
Provide exported or sample emails, documents, images, audio, meeting notes, or chat files to an AI processing pipeline. This tests whether the core grouping and timeline-generation capability works without first building live integrations.
Approach B - Limited-integration MVP
Connect a limited number of tools (for now), currently proposed as Gmail, Google Calendar, and Slack, so that selected project information can be collected automatically.

Phase 2. Architecture Workflow & Steps Needed Questions
Implementation steps have not yet been finalized. This phase is intentionally divided into questions and provisional recommendations.
Preliminary recommendations - revise later
Begin with a controlled file-based prototype to validate semantic grouping, event extraction, and timeline construction before adding authentication and synchronization complexity.
Use a narrow set of inputs first: exported email messages, meeting/calendar records, and common text-based documents. Add images and audio after the text workflow is reliable.
Build the processing flow as separate modules: ingestion -> extraction and normalization -> relationship detection -> project grouping -> event/action extraction -> timeline generation -> user review -> dashboard.
Combine deterministic metadata signals with semantic similarity. Dates, participants, thread identifiers, file links, and explicit project names should support rather than be replaced by LLM reasoning.
Keep every generated event connected to its original source and include a confidence level or explanation for uncertain project assignments.
Store user corrections and use them as evaluation feedback before automatically treating them as permanent model behavior.
After the core pipeline works, add one integration first. Gmail is the strongest initial candidate because it supplies content, participants, timestamps, threads, and attachments in one source.
Add Google Calendar next to improve meeting and date information. Add Slack only after the project-grouping behavior works across the first two sources.

Phase 3. Release Date
A calendar release date should be selected after the Phase 1 scope and Phase 2 implementation approach are confirmed. The schedule below is a recommended relative plan, not a fixed commitment.
Provisional release recommendation - revise later
Stage 1: confirm the primary user, use case, MVP boundary, and success criteria; prepare a controlled evaluation dataset.
Stage 2: build ingestion, text extraction, metadata normalization, and storage for the selected inputs.
Stage 3: build semantic relationship detection, project grouping, and confidence scoring.
Stage 4: extract timeline events, decisions, deadlines, and action items; preserve source references.
Stage 5: build the dashboard and user correction workflow; run end-to-end testing.
Stage 6: conduct a small user test, fix critical defects, document known limitations, and release the prototype.
If the available period is shorter, release a file-based prototype and postpone live integrations. If more time is available, add Gmail only after the core workflow passes evaluation.
